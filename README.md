# Mini Circle

The site uses the Mini Circle name and the supplied brand direction: a turquoise-to-blue gradient with red and yellow overlapping arcs. The reusable vector logo is [`mini-circle-logo.svg`](./mini-circle-logo.svg); the interface uses clean blue/cyan selected states, subtle color accents, and restrained motion while reserving red and yellow for small brand highlights. The platform keeps its sport, reading, and learning community purpose under this brand.

## Social sharing

The **Share site** and **Share post** buttons open an accessible platform-choice dialog with WhatsApp, Facebook, X, Telegram, LinkedIn, email, the browser's native share sheet, and copy-link actions. WhatsApp is highlighted as the primary option. A post's share preview includes its organization, post text, event details (when present), and a direct link back to the post, formatted with readable line breaks. External sharing opens in a new tab when possible, leaving the site open. Individual member names are not added to the prefilled message; post text itself is included when the user chooses to share it.

The light, responsive interface is organized around five destinations: **Home** (social feed), **Discover** (groups, events, videos, and opportunities), **Matchday** (the featured Mini Circle League followed by local leagues), **Learn** (my learning, a grouped course catalogue, tutoring, and community study spaces), and **You** (profile and progress). A global search finds groups, posts, events, and courses; partner course pages also have course-specific search. Settings are available from the top bar and profile page for feed interests and quiet hours. Preferences are saved in this browser only. The desktop right rail contains only shortcuts to those areas rather than duplicating whole pages. Learning sections and organization course lists use expandable groups so the page stays scannable. Alerts and sharing remain in the top bar. Desktop views keep a consistent navigation, content column, and right rail; tablet and phone layouts collapse consistently, with safe-area-aware bottom navigation that adapts to admin items, single-column content, and wrapped form/action rows. Long tab strips and tables scroll within their own regions rather than expanding the page width. Controls have larger phone touch targets, and feeds load in batches. The share dialog supports keyboard focus, Escape-to-close, and return focus to the button that opened it.

## Profiles and organization branding

Members can update their display name and short bio, and upload or remove a profile avatar from **You → Customize your profile**. In this prototype, the Foundation demo role can edit any sample organization, while the Mamelodi Stars admin demo role can edit that sample page. The **Edit organization profile** section changes its name, type, summary, location, public website, contact email, brand color, logo, and banner. Uploaded images are cropped and optimized in the browser; image blobs are saved in IndexedDB and profile/organization text in local storage on that device. These are browser-local prototype settings, not shared accounts or production organization permissions. Use organization-approved images and public contact information; do not upload sensitive images or real children’s identifying details.

## Audience and feed relevance

The home and Discover pages explain the value for young people, parents, schools/clubs, and the wider community. The “For you” feed has editable Sport, Reading, Learning, Events, and Opportunities interests, adjustable in Settings. It ranks posts using those explicit choices plus groups followed or joined in the current session; newer posts stay ahead when relevance is tied. It does not rank by popularity or infer sensitive traits. Interest and quiet-hour choices are stored in this browser only. This is a transparent prototype rule, not a production recommendation service.

The product position is a trusted, organized community for sport, reading, and learning: professional organization pages and communications, with playful matchday energy rather than an endless feed. The stakeholder guide is explicit that child-safety reporting, staffed moderation, verified role workflows, consent, and privacy compliance must be built and reviewed before a public launch.

## Community study resources

Study notes, handouts, images, and short videos are part of each group's **Community** space, with a directory of community study spaces in Learn. Resources can optionally be associated with a course and opened from its discussion. The prototype accepts PDF, text, Office documents, common image formats, and MP4/WebM video up to 15 MB; it saves resource records and file blobs in this browser's IndexedDB only. This is a local interaction demo, not collaboration between students or devices. Do not upload real children's personal, confidential, or identifying information. A real shared library requires authenticated membership, managed object storage, malware/content checks, moderation and retention rules, quotas, and a reviewed safeguarding workflow.

## Tutoring and video sessions

Learn and organization Community pages include an in-product tutoring workspace. An adult freelancer can create a local tutor profile and list independent sessions with a subject, learning goals, format, capacity, time, and Google Meet, Zoom, or Jitsi link. Organization coordinators can publish and manage sessions for their community. Tutors and coordinators can review requests, confirm or decline learners, cancel upcoming sessions, record attendance after a session, and save follow-up notes. A learner with a demo profile can request an offered format; active requests temporarily lock a session to one format to prevent mixing group and 1:1 bookings. A 1:1 request requires the learner to acknowledge that a parent/guardian or partner coordinator knows about and can supervise it. Group requests use the listed capacity; 1:1 sessions accept one learner. Confirmed learners can open an optional meeting link, and tutors can open the link from their roster.

Session listings and requests are stored only in the current browser's local storage. They do not reach a tutor or another learner, and the demo organization/tutor roles are not verified. Use no real child information or personal meeting links. A production tutoring service needs a shared authenticated scheduling backend, verified educator permissions, guardian-visible session details and consent, moderator/reporting workflows, reliable capacity and cancellation handling, and legal/privacy review (including POPIA where applicable). Google sign-in is not configured; if added later, it should be transparent, optional authentication rather than covert tracking.

## Mentoring and independent professionals

Learn includes a searchable mentor directory and a profile-draft flow for adult freelancers who do not have their own website. A profile can present a display name, expertise, a short service description, and group or supervised 1:1 formats; it intentionally does not collect public contact details or portfolio links. Learners can request an introduction, with group introductions encouraged and an explicit parent/guardian or school-coordinator supervision acknowledgement required for 1:1 requests. Partner Community pages link into the directory, and the global search includes sample mentors.

Directory entries are illustrative and unverified. Profile drafts and introduction requests are saved in this browser only; they are not published, reviewed, delivered to mentors, or connected to another user. The profile form is not a freelancer marketplace, job board, payment service, or safeguarding check. Before launch, implement verified adult identity and qualifications, organization sponsorship and moderation, consented shared profiles, coordinator-managed introductions and scheduling, clear service terms and pricing, secure payments only if required, reporting/escalation, and POPIA/privacy review. Do not use the prototype to arrange real contact between adults and children.

## Partner value

The stakeholder guide now presents Mini Circle as a single branded home for partner announcements, events, courses, tutoring, mentoring referrals, and community resources, with shareable links for families and prospective members. It recommends starting with one program and reviewing aggregate participation before expanding. The guide's proposed impact measures (such as event participation, course completion, reading activity, and resource use) are product goals, not live analytics; current partner pages, counts, staff identities, and sample mentor profiles are local prototype content. A real institutional service needs verified organization ownership and staff permissions, shared data, consent, retention controls, moderation, accessibility, operational support, and safeguarding processes before claiming those outcomes.

## Local leagues

Matchday keeps the built-in **Mini Circle League** fixtures and table at the top as the featured competition. Clubs can register a local league with a founding club; other clubs can request entry, and the league administrator can approve them. League administrators can schedule and edit fixtures. The demo also lets the league administrator switch to a registered club-admin role, which can update only fixtures involving that club. Saved scores calculate played, win/draw/loss, goal difference, and points automatically (3 for a win, 1 for a draw). Fixture and result updates create posts under both clubs, so they appear in the social feed and in the Following feed for members who follow those clubs.

This is a browser-local prototype: leagues, roles, fixtures, results, and posts are not synchronized across users or devices. The role switch is a demonstration, not authentication or proof of club authority; generated feed posts and any follower alert are also local to this browser. Before a real league launch, add verified club registration, authenticated league and club permissions, server-side fixture/result history, dispute/correction handling, and shared feed/notification delivery.

## Prototype content storage and growth

Community posts, demo organizations, and feed interests are saved in browser storage (up to the latest 250 posts) and restored after refresh on that same browser. This is a prototype convenience, not shared storage: posts are not synchronized between visitors or devices, browser data can be cleared, and the browser is not a secure database. The demo profile, follows, and learning progress are not connected to real user accounts. Do not store private information or use this storage for real children's accounts.

The Supabase schema foundation is in [`supabase/migrations/20261016000000_community_foundation.sql`](./supabase/migrations/20261016000000_community_foundation.sql). It creates verified organizations, private member approval status, moderation-first posts and comments, member reports, feed indexes, and per-account submission limits. Public clients can only read published content; posting requires an authenticated, approved account and creates pending content. Review/publishing and approval require a trusted Supabase administrator. The app is not connected to this schema yet.

Before opening the service to a growing user base, configure a Supabase project, apply and test the migration, and connect a reviewed sign-in and parent/guardian-consent flow. Add object storage plus a CDN for approved video and image uploads, backups and retention controls, audit logs, and accessibility/performance monitoring before turning on user-generated media. Keep sharing user-initiated and avoid importing contacts or sending unsolicited messages. This repository is currently a static HTML prototype and contains no project URL, publishable key, auth flow, deployment configuration, or database connection; do not add a service-role key to the browser.

For useful previews, the page includes basic Open Graph and X card metadata. Before launch, host the site on a public HTTPS domain and replace the generic preview metadata with the approved brand description and a branded preview image. Social platforms read preview metadata from the page HTML on their servers, so JavaScript-only metadata changes are not enough.

## Before production

This is a single-file prototype, not a production social-network integration. Posts persist only in the current browser, so IDs and links are not shared or dependable across visitors and devices. Organization announcements and course notifications are also prototype-local; they do not deliver to other users. Production sharing needs server-side persistent post records, stable public URLs, and server-rendered or edge-generated preview metadata for each shareable page. Do not add social sign-in, platform API credentials, tracking pixels, or automatic cross-posting without a reviewed privacy and child-safety design; use platform-specific APIs only if there is a clear need and appropriate consent.
