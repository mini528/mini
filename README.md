# Mini Circle

The site uses the Mini Circle name and the supplied brand direction: a turquoise-to-blue gradient with red and yellow overlapping arcs. The reusable vector logo is [`mini-circle-logo.svg`](./mini-circle-logo.svg); the interface uses clean blue/cyan selected states, subtle color accents, and restrained motion while reserving red and yellow for small brand highlights. The platform keeps its sport, reading, and learning community purpose under this brand.

## Social sharing

The **Share site** and **Share post** buttons open an accessible platform-choice dialog with WhatsApp, Facebook, X, Telegram, LinkedIn, email, the browser's native share sheet, and copy-link actions. WhatsApp is highlighted as the primary option. A post's share preview includes its organization, post text, event details (when present), and a direct link back to the post, formatted with readable line breaks. External sharing opens in a new tab when possible, leaving the site open. Individual member names are not added to the prefilled message; post text itself is included when the user chooses to share it.

The page uses a light, responsive social-feed layout with five main destinations: Home, Explore, Matchday, Courses, and You. Desktop views share the same navigation, content-column, and right-rail grid so switching tabs does not shift the page; tablet and phone layouts collapse consistently. Library and Events are accessible from Explore; Alerts are in the top bar. On phones, navigation stays in a safe-area-aware bottom bar, the header truncates long titles instead of overflowing, post actions remain tappable, tables scroll horizontally, and course/organization grids collapse to one column. Feeds reveal posts in batches instead of rendering an ever-growing list. The share dialog supports keyboard focus, Escape-to-close, and return focus to the button that opened it.

## Audience and feed relevance

The home and Explore pages explain the value for young people, parents, schools/clubs, and the wider community. The “For you” feed has editable Sport, Reading, Learning, Events, and Opportunities interests. It ranks posts using those explicit choices plus groups followed or joined in the current session; newer posts stay ahead when relevance is tied. It does not rank by popularity or infer sensitive traits. Interest choices are stored in this browser only. This is a transparent prototype rule, not a production recommendation service.

The product position is a trusted, organized community for sport, reading, and learning: professional organization pages and communications, with playful matchday energy rather than an endless feed. The stakeholder guide is explicit that child-safety reporting, staffed moderation, verified role workflows, consent, and privacy compliance must be built and reviewed before a public launch.

## Community study resources

Study notes, handouts, images, and short videos are part of each group's **Community** space, with quick links from Explore and Courses. Resources can optionally be associated with a course and opened from its discussion. The prototype accepts PDF, text, Office documents, common image formats, and MP4/WebM video up to 15 MB; it saves resource records and file blobs in this browser's IndexedDB only. This is a local interaction demo, not collaboration between students or devices. Do not upload real children's personal, confidential, or identifying information. A real shared library requires authenticated membership, managed object storage, malware/content checks, moderation and retention rules, quotas, and a reviewed safeguarding workflow.

## Tutoring and video sessions

The Courses page and each organization Community page include a tutoring hub. In the demo, an organization coordinator can list a subject, time, supported format (group, 1:1, or either), capacity, and video provider. A learner with a demo profile can request only an offered format; the first active request temporarily locks the session to that format to avoid mixing 1:1 and group requests. Group requests use the listed capacity, while a 1:1 session accepts one learner. Requests remain pending until the organization confirms or declines them. An approved learner can open the optional Google Meet, Zoom, or Jitsi URL, but the provider links are external and are not integrated with Mini Circle accounts or scheduling.

Session listings and requests are stored only in the current browser's local storage. They do not reach a tutor or another learner, and the demo organization/tutor roles are not verified. Use no real child information or personal meeting links. A production tutoring service needs a shared authenticated scheduling backend, verified educator permissions, guardian-visible session details and consent, moderator/reporting workflows, reliable capacity and cancellation handling, and legal/privacy review (including POPIA where applicable). Google sign-in is not configured; if added later, it should be transparent, optional authentication rather than covert tracking.

## Local leagues

Matchday keeps the built-in **Mini Circle League** fixtures and table at the top as the featured competition. Clubs can register a local league with a founding club; other clubs can request entry, and the league administrator can approve them. League administrators can schedule and edit fixtures. The demo also lets the league administrator switch to a registered club-admin role, which can update only fixtures involving that club. Saved scores calculate played, win/draw/loss, goal difference, and points automatically (3 for a win, 1 for a draw). Fixture and result updates create posts under both clubs, so they appear in the social feed and in the Following feed for members who follow those clubs.

This is a browser-local prototype: leagues, roles, fixtures, results, and posts are not synchronized across users or devices. The role switch is a demonstration, not authentication or proof of club authority; generated feed posts and any follower alert are also local to this browser. Before a real league launch, add verified club registration, authenticated league and club permissions, server-side fixture/result history, dispute/correction handling, and shared feed/notification delivery.

## Prototype content storage and growth

Community posts, demo organizations, and feed interests are saved in browser storage (up to the latest 250 posts) and restored after refresh on that same browser. This is a prototype convenience, not shared storage: posts are not synchronized between visitors or devices, browser data can be cleared, and the browser is not a secure database. The demo profile, follows, and learning progress are not connected to real user accounts. Do not store private information or use this storage for real children's accounts.

The Supabase schema foundation is in [`supabase/migrations/20261016000000_community_foundation.sql`](./supabase/migrations/20261016000000_community_foundation.sql). It creates verified organizations, private member approval status, moderation-first posts and comments, member reports, feed indexes, and per-account submission limits. Public clients can only read published content; posting requires an authenticated, approved account and creates pending content. Review/publishing and approval require a trusted Supabase administrator. The app is not connected to this schema yet.

Before opening the service to a growing user base, configure a Supabase project, apply and test the migration, and connect a reviewed sign-in and parent/guardian-consent flow. Add object storage plus a CDN for approved video and image uploads, backups and retention controls, audit logs, and accessibility/performance monitoring before turning on user-generated media. Keep sharing user-initiated and avoid importing contacts or sending unsolicited messages. This repository is currently a static HTML prototype and contains no project URL, publishable key, auth flow, deployment configuration, or database connection; do not add a service-role key to the browser.

For useful previews, the page includes basic Open Graph and X card metadata. Before launch, host the site on a public HTTPS domain and replace the generic preview metadata with the approved brand description and a branded preview image. Social platforms read preview metadata from the page HTML on their servers, so JavaScript-only metadata changes are not enough.

## Before production

This is a single-file prototype, not a production social-network integration. Posts persist only in the current browser, so IDs and links are not shared or dependable across visitors and devices. Organization announcements and course notifications are also prototype-local; they do not deliver to other users. Production sharing needs server-side persistent post records, stable public URLs, and server-rendered or edge-generated preview metadata for each shareable page. Do not add social sign-in, platform API credentials, tracking pixels, or automatic cross-posting without a reviewed privacy and child-safety design; use platform-specific APIs only if there is a clear need and appropriate consent.
